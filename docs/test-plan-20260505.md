## Affected Modules

- **compiler.py** — 强模型调用 + DAG JSON Schema 校验
- **worker.py** — 弱模型循环 + 迭代控制
- **sandbox.py** — 子进程执行 + 资源限制
- **reviewer.py** — 强模型审核 + pass/fail 判定
- **main.py** — CLI 入口 + 编排 + 重启恢复
- **types.py** — 共享数据类定义

## Critical Test Cases

### compiler.py（5 条路径）
1. 合法 JSON DAG 正常返回 → mock 强模型返回有效 JSON
2. 非法 JSON 触发重试 → mock 第一次返回 `{invalid`, 第二次返回有效 JSON
3. 2 次重试后仍非法 → 抛出 CompilationError
4. API 超时 → mock side_effect Timeout → 退避重试成功
5. API 3 次超时 → 任务标记 failed

### worker.py（5 条路径）
1. 一次生成通过 → mock 弱模型返回正确代码
2. 3 次迭代通过 → mock 依次返回 [bug代码, 修复但仍有bug, 正确代码]
3. 10 次迭代失败 → mock 持续返回错误代码 → 返回 NodeResult(status=failed)
4. 429 退避恢复 → mock 依次返回 [429, 429, 正确代码]
5. 语法错误修复 → mock 返回语法错误代码 → worker 读 stderr 修复

### sandbox.py（4 条路径）
1. 正常执行通过 → 代码 + 测试 → exit_code=0
2. 测试失败 → 代码 + 失败测试 → exit_code=1, 捕获 stderr
3. CPU 超时 → 死循环代码 → SIGXCPU → SandboxResult(timed_out=True)
4. 内存超限 → 大数组分配 → SIGSEGV → SandboxResult(memory_exceeded=True)

### reviewer.py（3 条路径）
1. PASS → mock 强模型返回 "PASS"
2. FAIL 传回重做 → mock 返回 "FAIL: node_id — reason — suggestion"
3. FAIL 累积 3 次 → 任务失败

### main.py 集成测试（3 条路径）
1. 完整闭环 → 编译通过 → 所有节点通过 → 审核 PASS → outputs/ 写入文件
2. 编译失败 → 任务标记 failed → 非零退出码
3. 重启恢复 → SQLite 中有 executing 状态任务 → 未完成节点重新入队

## Edge Cases
- 空任务描述 → 编译器应拒绝或返回空 DAG
- 单节点 DAG（无依赖）→ worker 正常处理
- 含循环依赖的 DAG → JSON Schema 校验应拒绝
- 超长任务描述 → 强模型 prompt 是否超 token 限制
- 并发写入 SQLite → WAL 模式 + 100ms 退避
